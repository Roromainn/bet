===============================================================================
DI CONTAINER REGISTRATION
===============================================================================

Method 1: Register Core Services
──────────────────────────────
services.AddBetTrackerCoreServices();
    → Registers IBetCalculationService → BetCalculationService (Scoped)


Method 2: Register Repositories
───────────────────────────────
services.AddBetTrackerRepositories();
    → Registers IRepository<T> → Repository<T> (Scoped, generic)
    → Registers IBookmakerRepository → BookmakerRepository (Scoped)
    → Registers IBetRepository → BetRepository (Scoped)


Full Setup in Application Startup:
──────────────────────────────────
var services = new ServiceCollection();

// Register DbContext
services.AddScoped<BetTrackerContext>();

// Register repositories and services
services.AddBetTrackerRepositories();
services.AddBetTrackerCoreServices();

// Build service provider
var provider = services.BuildServiceProvider();

===============================================================================
CALCULATION SERVICE FORMULAS
===============================================================================

LAY BET EV:
───────────
Used for arbitrage/lay betting strategies

Formula: EV = back_stake * (back_odds - 1) - lay_stake * lay_odds

Context:
  - Back bet: Money placed on outcome at first bookmaker
  - Lay bet: Money placed against outcome at second bookmaker
  - Positive EV: Profitable opportunity
  - Negative EV: Loss expected


MATCHED BET PROFIT:
───────────────────
Used for matched betting (guarantee profit from bonuses)

Formula: Profit = min(stake1 * odds1, stake2 * odds2) - total_stakes

Context:
  - Betting both sides to guarantee profit
  - Often used with free bets or bonus requirements


COVERAGE LOSS:
──────────────
Used to measure imperfect bet matching

Formula: Loss = total_stakes - min(outcome1, outcome2)

Context:
  - Represents unhedged portion of bets
  - Should be minimized with proper stake sizing

Key Relationships:
- Bookmaker → Many Offers (one-to-many)
- Offer → Many Calculations (one-to-many)

- Bookmaker → Many Bankroll Movements (cascade delete)
- Offer → Many Bankroll Movements (cascade delete)


===============================================================================
LIFETIME MANAGEMENT
===============================================================================

All services and repositories use SCOPED lifetime:

Scoped Lifetime Benefits:
  ✓ New instance per request/operation
  ✓ Same DbContext instance within scope
  ✓ Proper change tracking
  ✓ Lazy loading support
  ✓ No memory leaks
  ✓ Thread-safe with async/await

Usage in Web Context:
  - One scope per HTTP request
  - Automatic disposal after request completes

Usage in Desktop Context:
  - Create scope for each user operation
  - Dispose scope when operation completes
